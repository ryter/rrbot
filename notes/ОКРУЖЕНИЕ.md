# Состояние окружения (23.10) — чтобы продолжить после перезагрузки

## Эмулятор вылетает: графический буфер (24.10)

Симптом: `adb exec-out screencap -p` отдаёт файл в **0 байт**, `adb shell`
начинает висеть, на рабочем столе появляются уведомления
«Process crashed: surfaceflinger» и
«Process crashed: android.hardware.graphics.allocator@4.0-…».

Причина (по логам контейнера):

```
E/GraphicBufferAllocator: Failed to allocate (941 x 1030) layerCount 1 format 1 usage b33: 5
E/SurfaceFlinger: captureScreenCommon: Buffer failed to allocate: 5
```

Графический буфер SurfaceFlinger (экран 941×1030) не создаётся: у контейнера
сломался `minigbm` поверх GPU хоста (i915). SurfaceFlinger падает и
перезапускается, контейнер «замерзает» — снимок экрана больше не снимается.
Чаще всего это происходит после запуска игры (Unity переключает режим
отображения) — но не каждый раз: в 24.10 воспроизводилось 3 раза из 5
запусков.

**Лечится только перезапуском контейнера** (не сессии!):

```bash
waydroid session stop
echo '<sudo-пароль>' | sudo -S systemctl restart waydroid-container
setsid waydroid session start > /tmp/opencode/session_start.log 2>&1 &
setsid waydroid show-full-ui > /tmp/opencode/show_ui.log 2>&1 &
bash tools/waydroid_net.sh '<sudo-пароль>'      # сеть после рестарта контейнера
```

`waydroid session stop` + `waydroid session start` **не помогает**: буфер
остаётся сломанным, screencap по-прежнему пустой. После рестарта контейнера
сеть действительно ломается (veth-пара не совпадает), но `waydroid_net.sh`
её чинит.

`tools/battle_loop.sh` теперь делает обе вещи: сначала пробует перезапуск
сессии, а если кадр всё ещё пустой — перезапускает контейнер.

## Эмулятор

```bash
# 1. поднять сессию (в фоне!)
setsid waydroid session start > /tmp/opencode/session_start.log 2>&1 &
setsid waydroid show-full-ui > /tmp/opencode/show_ui.log 2>&1 &

# 2. починить сеть (нужен sudo) — без этого игра висит на «Проверка обновлений»
bash tools/waydroid_net.sh '<sudo-пароль>'

# 3. ждать, пока adb увидит устройство
adb devices   # должно быть: 192.168.240.112:5555  device
```

Если `adb devices` пусто:

```bash
adb kill-server && adb start-server
adb connect 192.168.240.112:5555
```

## Сеть (диагностика)

* VPN-интерфейс хоста `amn0` — MTU **1376**, гостевой `eth0` должен быть
  тоже 1376 (иначе крупные TCP-сегменты не проходят через туннель).
* Проверка из гостя:
  ```bash
  adb shell 'ip link show eth0 | grep -o "mtu [0-9]*"'      # должно быть 1376
  adb shell 'curl -sS -o /dev/null -w "%{http_code}\n" --max-time 20 https://my.games/'
  ```
  `200` — сеть в порядке; таймаут — MTU снова 1500, чинить
  `tools/waydroid_net.sh`.
