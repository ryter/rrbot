# Продолжить работу: Rush Royale, бот в эмуляторе

Краткая точка входа. Подробности — в `HANDOFF.md` (состояние проекта),
`README.md` (как оно устроено) и `cpp/README.md` (C++-бот).

## Что сейчас работает

* Бот проходит меню, **выходит из боя по «Продолжить»** и начинает следующий
  бой сам. По умолчанию играет в **PvP** (`--pvp`), для Co-Op —
  `BATTLE_MODE=coop` в `tools/battle_loop.sh`.
* Читает энергию (цифры в области числа; область переведена в пиксели
  устройства 941×1030).
* **Призывает юнитов** (клик по виджету).
* **Нажимает умение героя** (круглая кнопка справа внизу), когда откат
  кончился: у готового умения вокруг кнопки есть жёлтое свечение, у
  «на откате» его нет. Ключ `--no-ability` отключает.
* **Сливает одинаковых пешек** — перетаскивает одну на другую. Работает
  вживую: на кадрах после слияния на месте цели появляется крупный юнит
  **другой формы** (результат слияния — случайная карта из колоды).
  Успешных слияний ~60 % попыток; остальные — пары, которые игра не
  принимает, и бот такие пары и клетки больше не пробует.
  **Важно:** результат слияния надо проверять по тому, что пешка-источник
  исчезла, а не по «на месте цели стоит юнит» — у слитого юнита форма не
  круглая, и детектор его не видит (из-за этого слияния и считались
  неудачными).
* **Играет и в Co-Op («Подземелья»)** — там своё поле устроено иначе:
  вместо цветных плиток две комнаты, обнесённые бежевыми стенами. Бот
  находит поле по стенам (`rr::find_arena_dungeon`), видит своих юнитов
  (медиана 8, максимум 15) и сливает их.
* **Ранга на поле нет** (выяснено 23.10, см. `notes/ЗАДАЧА1_РАНГ.md`):
  форма основания кодирует **тип карты**, а не ранг. Пара одного типа
  сливается в 92 % случаев (если похожи портреты), пара разных типов —
  примерно в 47 %. Поэтому бот выбирает пару по оценке успеха
  (`rr::merge_success_estimate`): похожесть портретов + тип карты +
  разница размеров.
* Планировщик C++ и Python дают одни и те же числа (тест
  `tests/test_cpp_planner.py`), и планировщик **выигрывает у случайного
  выбора** (100 % против 52.5 % на волнах 4/13; 45 % против 7.5 % на 5/12) —
  после того, как выбор линии заменён на контр-пуш с защитой прорвавшегося.
* Зрение на живых кадрах ищет юниты **по круглому основанию**, а не по
  спрайту: recall 0.93, precision 0.94, ошибка позиции 2 px (было 0.45 /
  0.57 / 9.9 px).

## Co-Op («Подземелья») и обновление игры 24.10

**Поле в «Подземельях» ищется по стенам, а не по плиткам.** В режиме Co-Op
на карте нет цветных плиток: там две комнаты (сверху чужая, снизу наша),
обнесённые бежевыми стенами, и дорога между ними. Поиск (`rr::find_arena_dungeon`):

1. бежевые стены — колонки, где преобладает бледный бежевый цвет;
2. своя комната — между самой правой стеной слева от центра кадра и самой
   левой справа;
3. высота комнаты — по вертикальному куску правой стены (ближние куски
   склеиваются: стена местами в тени).

По плиткам высоту комнаты определять нельзя: когда комната забита юнитами,
плитки от них закрыты и строки распадаются на мелкие куски.

**Цвета поменялись после обновления игры (24.10).** Стена теперь не кремовая
(V≈250), а тёмно-бежевая (V≈185, S≈89); плитки — V≈217, S≈105. Различаем
по насыщенности: маска стен `H 10..30, S 40..100, V 175..255`. Со старой
маской (V≥225) стена не находилась в половине кадров, арена «терялась»,
и бот не видел пешек.

Замер по 291 боевому кадру Co-Op: **арена найдена в 100 % кадров**, границы
своей комнаты стабильны — `(275, 575, 392×249)` в 287 кадрах из 291
(повторный замер на свежей партии: 64/64, та же граница в 63 кадрах).

**Что осталось в неудачных слияниях.** После того как размер пешек стал
частью правила выбора пары (`kMergeSizeMax`), оставшиеся неудачи этим
объяснить уже нельзя: в Co-Op у неудачных пар разница размеров такая же,
как у удачных (3.8 % против 4.4 %), и основания у всех круглые. Остаётся
**разный тип карты** (это подтвердили замеры `tools/merge_pairs_stats.py`:
пара одного типа сливается в 92 % случаев, пары разных типов — в 47 %),
и именно его учитывает `rr::merge_success_estimate`. Гипотеза «юнит был
занят атакой, поэтому слияние не вышло» **не подтвердилась**: у неудачных
пар вспышек (белых пикселей) вокруг юнитов меньше, чем у удачных
(88 против 174 у источника, 51 против 116 у цели).

**Экран выбора модификатора** в новом дизайне: тёмная панель с двумя
серо-синими карточками. Прежний поиск (одна широкая светлая карточка) не
узнавал этот экран, и бот топтался по кругу. Теперь серо-синие карточки
ищутся по цвету и размеру (значок вырезает из карточки кусок — порог
площади 9000·scale²), жмётся значок первой карточки.

**Значок модификатора реагирует только на касание** (`adb shell input tap`),
клик мышью по нему не даёт эффекта: для этого в бэкенд добавлен
`tap_touch`, а экран модификатора жмётся через него.

**Прочие правки навигации:**

* окно «Внимание! Просмотр рекламы увеличит вашу награду» — бот жал
  крестик и попадал в бесконечный цикл; теперь кнопка окна («Продолжить»)
  приоритетнее крестика;
* окно «Обновление ресурсов» (после обновления игры): две синие кнопки,
  жмётся правая («Подтвердить»);
* «Назад» в главном меню закрывает игру (игра спрашивает «выйти из
  игры?», бот застревает в вопросе) — на главном меню и на экранах Co-Op
  «Назад» больше не жмётся; всего за проход «Назад» жмётся не больше трёх
  раз, а если игра всё-таки закрылась — бот возвращает её на экран;
* «Идёт бой» больше не срабатывает на экранах меню: у этажей Co-Op тоже
  есть числа и флакон, поэтому признаком боя считается ещё и найденное
  поле.

## Если игра зависла на загрузке

«Проверка обновлений» и пустой чёрный экран — контейнер без сети: у гостя
нет маршрута по умолчанию, а MTU должен быть 1376 (хост ходит в интернет
через VPN). Лечится:

```bash
bash tools/waydroid_net.sh <sudo-пароль>
```

Если не помогло — перезапустить сессию (`waydroid session stop` →
`setsid waydroid session start &` → `waydroid show-full-ui` → скрипт выше).

## Если эмулятор «замёрз» (кадр пустой, adb не отвечает)

Это не сеть, а сломанный графический буфер контейнера: SurfaceFlinger не
может создать буфер экрана 941×1030 (`GraphicBufferAllocator: Failed to
allocate ... : 5`), он падает, и `screencap` отдаёт 0 байт.

**Помогает только перезапуск контейнера** (перезапуск сессии не помогает):

```bash
waydroid session stop
echo '<sudo-пароль>' | sudo -S systemctl restart waydroid-container
setsid waydroid session start > /tmp/opencode/session_start.log 2>&1 &
setsid waydroid show-full-ui > /tmp/opencode/show_ui.log 2>&1 &
bash tools/waydroid_net.sh '<sudo-пароль>'     # сеть после рестарта контейнера
```

`tools/battle_loop.sh` делает это сам (сначала пробует сессию, потом
контейнер). Подробности — `notes/ОКРУЖЕНИЕ.md`.

**1. ~~Уточнить определение ранга.~~ ЗАКРЫТО (23.10).** Ранга на поле
не видно: форма основания кодирует **тип карты**, а не ранг (замеры в
`notes/ЗАДАЧА1_РАНГ.md`). Правило «предпочитать круглое основание» убрано
из кода; вместо него бот оценивает вероятность успеха пары
(`rr::merge_success_estimate`) — похожесть портретов + тип карты +
разница размеров. Инструменты замера: `tools/merge_pairs_stats.py`,
`tools/merge_policy_eval.py`, `tools/merge_attempts.py`,
`tools/merge_summary.py`.

**2. ~~Понять, почему игра отвергает часть пар.~~ ЗАКРЫТО (23.10).**
Причины две: **разный тип карты** (пара разных типов сливается примерно
в 47 % случаев против 92 % у пар одного типа) и **разный ранг** (его на
поле не видно, и игра сама откажет). Второе бот лечит чёрными списками
неудачных пар и клеток.

**3. Планировщик пока не влияет на игру.** Он советует, кого звать и на
какую линию, но бот зовёт того юнита, чья карточка выбрана в колоде
(клик по виджету призыва). Чтобы следовать совету планировщика, нужно
ещё выбирать карточку в колоде и ставить юнита на нужную линию
(перетаскиванием карточки на поле).

**4. ~~Держать доску забитой первым рангом.~~ ЗАКРЫТО (24.10).** Бот следит
за свободными клетками: поле — сетка 5×3 (15 клеток), и когда свободных
клеток нет, призыв всё равно не создаёт юнита (виджет гаснет). Занятость
считается по клеткам (пустая клетка — ровная плитка, занятая — основание с
юнитом), а не по найденным юнитам: круглых оснований хватает не всем, и по
ним доска выглядела бы свободной. Когда свободных клеток ≤ 2, бот
переходит на мягкие правила слияния. Подробности и замеры —
`notes/ЗАДАЧА4_ДОСКА.md`.

## Окружение

* Эмулятор: `waydroid session start` (в фоне!), `waydroid show-full-ui`,
  `bash tools/waydroid_net.sh <sudo-пароль>` — или всё это сразу через
  `bash tools/start_emulator.sh <sudo-пароль>`.
* `systemctl restart waydroid-container` **ломает сеть** контейнера (veth-пара
  не совпадает, adb даёт «No route to host»); помогает обычный
  `waydroid session stop` + `waydroid session start`.
* Контейнер иногда замерзает: `screencap` отдаёт файл в 0 байт, adb не
  отвечает. Лечится перезапуском сессии и `tools/waydroid_net.sh`; боевой
  цикл делает это сам, если задан `WAYDROID_SUDO_PASSWORD`.
* Раскладка HUD — в пикселях устройства (941×1030). Сменится размер окна —
  поедут все области; чинить: `adb shell wm size 941x1030`.
* Если бот стартует, пока `adb` ещё не авторизован, он читает неверный
  размер кадра и растягивает картинку — тогда навигация не работает.
  После перезагрузки сначала дождись `adb devices` со статусом `device`.
