# Эталоны юнитов мобильного клиента, версия 2 (`assets/real_emulator2/`)

Набор собран `tools/collect_units_emulator2.py` из тех же канонических кадров
(`assets/eval_real/frames`, 24 кадра), что и первый набор
(`assets/real_emulator/`). Первый набор и его сборщик не тронуты.

## Что внутри

| файл | что это |
|---|---|
| `unit_em_NN_*.png` | эталоны для детектора: квадратный вырез вокруг юнита (тело + кольцо основания) **в масштабе канонического кадра** |
| `unit_em_NN_*_1.png` … `_4.png` | те же юниты в других кадрах анимации (детектору нужен не один повёрнутый силуэт) |
| `sprite/unit_em_NN_*.png` | тело юнита без основания (силуэт по чёрной обводке) |
| `index.tsv` | манифест: файл, размер, сколько встреч, цвет тела и основания, примеры позиций |
| `samples.tsv` | **новое**: каждый найденный юнит — кадр, позиция, радиус основания и его тип. По нему измеряется точность определения *типа* |
| `types.tsv` | соответствие «эталон → карточка в колоде» (перенесено из первого набора) |

## Чем этот набор лучше первого

**Эталоны не растягиваются.** Первая версия приводила вырез к каноническому
радиусу основания (`REF_RADIUS = 31 px`), а радиус основания в каноническом
кадре около 29 px: получалось, что эталон на 8-10 % крупнее юнита на поле,
и совпадение с ним падало. Здесь вырез берётся ровно таким, какой он есть в
кадре, поэтому эталон совпадает с юнитом как есть.

Кроме того, в первом наботе радиус основания искался по скачку яркости вдоль
окружности — этот способ цепляется за *внутренний* край кольца и занижает
радиус на несколько пикселей. Здесь радиус выбирается по тому, насколько
круглой оказалась граница (та же мера, что и в детекторе).

Ещё в наборе 5 вариантов на тип вместо трёх (юниты анимируются).

## Замер

```bash
# положение юнитов (по основаниям) — то же, что и в детекторе бота
.venv/bin/python tools/evaluate_vision_cpp.py --mode real \
    --templates assets/real_emulator2 --threshold 0.60 --max-per-template 12

# точность определения типа по манифесту samples.tsv
.venv/bin/python tools/eval_types.py --templates assets/real_emulator2
```

Точность определения типа (по манифесту `samples.tsv`, 327 юнитов):

| набор эталонов | тип определён верно |
|---|---|
| `assets/real_emulator` (первый) | 0.384 |
| `assets/real_emulator2` (этот) | **0.545** |

## Пересобрать

```bash
.venv/bin/python tools/collect_units_emulator2.py \
    --frames assets/eval_real/frames --truth assets/eval_real/truth.tsv \
    --out assets/real_emulator2 --types-count 8 --variants 5
```

Сбор детерминирован: повторный запуск даёт те же файлы.

## Ограничение

Соответствие «эталон → карточка в колоде» в `types.tsv` перенесено из первого
набора по описанию вида юнита (цвет тела на цвете основания). Группировка в
этом наборе считается по другому признаку, поэтому для части типов карточка
взята «по номеру эталона» (в таблице это помечено). Бот вживую пока
использует первый набор (`assets/real_emulator`), у него соответствие
проверено.
