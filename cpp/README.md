# Бот на C++

Основной вариант бота: живой режим на C++, без Python и без зависимости от
окна браузера. Python-версия (`rrbot/`) — прототип с симулятором, она
описана в корневом `README.md`.

```
src/
  common.hpp    раскладки интерфейса и правила кнопок
  layout.cpp    раскладки: веб-клиент и мобильный клиент
  capture.*     захват экрана (grim) и поиск холста по рамке
  mouse.*       виртуальная мышь: устройство uinput с осями ABS_X/ABS_Y
  adb.*         захват и ввод через Android-эмулятор (adb)
  game.*        окно, холст, перевод координат; бэкенды
  hud.*         цифры HUD, кнопки, правила навигации, защита от покупок
  main.cpp      цикл: меню -> бой -> призыв
  models.hpp    доменные модели: юниты, находки, состояние поля
  vision.*      поиск юнитов по эталонам (порт rrbot/vision.py — в работе)
  planner.*     планировщик (порт rrbot/planner.py — в работе)
```

## Сборка

```bash
cd cpp
make            # нужен OpenCV (opencv5) и libevdev
```

Зависимости в системе: `opencv` (пакет Arch, включая модуль `geometry` —
он нужен для перспективной коррекции поля), `libevdev`, `android-tools`
(для варианта с эмулятором).

`make` собирает два бинаря: `build/rrbot` — сам бот, и `build/rrvision` —
отдельную утилиту замера точности детекции (в работе, порт зрения с
Python).

В `Makefile` включено отслеживание зависимостей от заголовков (`-MMD -MP`
и `include *.d`). Без этого после правки `common.hpp` часть объектных
файлов оставалась со старой структурой `Layout` — и бот падал с
`free(): invalid pointer`. Если сомневаешься: `make clean && make`.

## Запуск

```bash
# веб-клиент в браузере: кадр с экрана, клик виртуальной мышью
./build/rrbot --steps 40

# клиент игры в Android-эмуляторе: кадр из устройства, клик через adb
./build/rrbot --backend adb --steps 40

# то же, но кликом настоящей мышью по окну эмулятора — клик видно
./build/rrbot --backend emulator --steps 40

# без кликов: только смотреть и считать
./build/rrbot --dry-run --steps 5

# показать, что бот видит в текущем кадре
./build/rrbot --backend adb --probe
```

### Ключи запуска

| ключ | что делает |
|---|---|
| `--backend desktop\|adb\|emulator` | источник кадра и способ клика (по умолчанию `desktop`) |
| `--steps N` | сколько шагов боя (по умолчанию 40) |
| `--rounds N` | сколько раундов подряд: бой → выход в меню → снова бой (по умолчанию 1) |
| `--dry-run` | только считать, не кликать |
| `--probe` | напечатать, что бот видит в кадре, и выйти |
| `--frame <файл>` | разобрать сохранённый кадр вместо живого (расклад — как у бэкенда) |
| `--digits-image <файл>` | прочитать число энергии прямо из картинки с цифрами |
| `--digits-dir <каталог>` | взять эталоны цифр из другого каталога (сравнение наборов); путь от корня проекта, если не абсолютный |
| `--learn <значение>` | сохранить глифы числа из кадра как эталоны цифр (значение пишется руками, например «60») |
| `--learn-dir <каталог>` | куда складывать новые эталоны (по умолчанию — текущий набор); путь от текущего каталога, каталог должен существовать |
| `--learn-max N` | сколько образцов максимум на цифру (по умолчанию 1000) |
| `--debug` | сохранять кадры боя в `--out` |
| `--show` | показывать клики в окне OpenCV (под Wayland окно не открывается) |
| `--out <каталог>` | куда складывать кадры (по умолчанию `/tmp/opencode/rrbot-cpp`) |

Примеры:

```bash
# мобильный клиент: что бот видит прямо сейчас
./build/rrbot --backend adb --probe

# три боя подряд: бой, выход в меню, снова бой
./build/rrbot --backend adb --steps 45 --rounds 3

# разбор сохранённого кадра — без запуска игры
./build/rrbot --backend adb --frame f0102.png

# прочитать число из выреза области энергии
./build/rrbot --backend adb --digits-image ../assets/test_energy/f0102.png

# сравнить два набора эталонов цифр
./build/rrbot --backend adb --digits-dir assets/digits_emulator_old \
    --digits-image ../assets/test_energy/f0102.png

# собрать эталоны из кадра: значение написано руками
mkdir -p /tmp/opencode/digits_new
./build/rrbot --backend adb --frame f0102.png --learn 60 \
    --learn-dir /tmp/opencode/digits_new --learn-max 6
```

`--learn` работает только вместе с `--frame`: глифы берутся из области
энергии кадра, слева направо. Число символов в значении должно совпадать с
числом глифов, иначе бот печатает «глифов N, а цифр в значении M» и
ничего не сохраняет.

## Бэкенды

| | desktop | adb / emulator |
|---|---|---|
| кадр | `grim` — снимок окна браузера | `adb exec-out screencap` — буфер устройства |
| клик | виртуальная мышь uinput | `adb shell input tap` или мышь по окну эмулятора |
| холст | ищется по рамке внутри окна | весь экран устройства |
| окно | можно перемещать, бот ищет заново | фиксированное разрешение |

Почему uinput, а не ydotool: тот эмулирует абсолютные координаты
относительными смещениями, и компоновщик применяет к ним свой масштаб —
`ydotool mousemove --absolute 500 500` уводил курсор в (1000, 1000).
Своё устройство с абсолютными осями попадает пиксель в пиксель.

## Раскладки

У веб-клиента и у мобильного клиента HUD устроен по-разному, поэтому
области заданы отдельно (`src/layout.cpp`):

* веб-клиент: холст 492×804, области сняты с настоящего браузера;
* мобильный клиент: кадр устройства 950×1034, области сняты с боя.

Пороги кнопок и размеры масштабируются под раскладку (`Layout::scale`).

Эталоны цифр тоже разные: у мобильного клиента другой шрифт, поэтому
для него собраны свои (`assets/digits_emulator`, 60 образцов).

## Чтение энергии

Число энергии читается по эталонам цифр: глиф нормализуется до 8×14 и
сравнивается с эталонами по корреляции; ниже порога 0.75 цифра
помечается как нераспознанная (`?`).

Два прохода по яркости (`src/hud.cpp`):

1. **яркое число** — порог яркости 150;
2. если яркого числа нет — **потускневшее**: на потолке энергии цифры гаснут
   и сереют, порог 95.

Если число не прочиталось совсем, бот берёт запасное значение — долю
заполнения зелёной шкалы. Область шкалы берётся из раскладки
(`Layout.mana_bar`), а не из захардкоженного прямоугольника веб-клиента:
в эмуляторе из старой области читался кусок арены и выдавался мусор вроде
`360.294`. В мобильном клиенте шкала тёмная, по цвету не читается, и
область в раскладке пустая — там запасного источника нет, число читается
только по цифрам.

Эталоны мобильного клиента (`assets/digits_emulator`) пересобраны из
настоящих боевых кадров: прежний набор был собран неверно — «6» не
совпадала сама с собой (0.55 вместо ~1.0), и энергия читалась как «?0».
Старый набор сохранён в `assets/digits_emulator_old` — на нём регрессионный
набор читается как 64/70, на новом 70/70.

### Регрессионный набор

`assets/test_energy/` — 70 вырезов области энергии и `labels.txt` с
ожидаемыми значениями. Проверка:

```bash
cd /home/lennistyle/rushroyale-lab
.venv/bin/python tools/check_digits.py     # -> прочитано верно: 70/70
```

Тот же набор проверяет тест `tests/test_cpp_digits.py` (в том числе
гаснущее число: вырез, затемнённый вдвое, читается тем же значением).

Сбор эталонов из боевых кадров и сбор набора — отдельные скрипты:

```bash
# эталоны из кадров, где число прочиталось уверенно
.venv/bin/python tools/collect_emulator_digits.py /tmp/opencode/frames2 --apply

# вырезы области энергии для регрессионного набора
.venv/bin/python tools/make_energy_fixtures.py \
    --frames /tmp/opencode/frames2 --labels /tmp/opencode/labels.txt \
    --out assets/test_energy
```

## Навигация по меню

* Кнопка «PvP» ищется **по надписи** (`assets/ui/text_pvp.png`), а не по
  цвету: рядом много оранжевого, и цветные пятна сливаются в один блок.
* Кнопка «Co-Op» — тоже по надписи (`assets/ui/text_coop.png`).
* **Крестик закрытия модального окна** ищется у правого края диалога, но
  порог задан в раскладке (`Layout.close_x_min`): 0.78 у веб-клиента и
  0.60 у мобильного. Прежний фиксированный порог 0.78 был рассчитан на
  веб-клиент, а в мобильном окно шире — крестик отбрасывался, и окно
  не закрывалось.
* После клика «PvP» бот **ждёт матч до 30 секунд**, проверяя, начался ли
  бой: экран подбора анимируется, и по кадру «изменилось» судить
  бесполезно. Если соперник не нашёлся дважды подряд — бот переключается
  на Co-Op.
* **Боевой цикл сначала проверяет, что бой идёт**: на экране итогов в
  области энергии лежит совсем другое, бот считывал оттуда случайные
  числа и мог кликнуть в пустое место.

## Что бот умеет

* находит холст игры и окно браузера;
* читает энергию по эталонам цифр (яркое число, иначе потускневшее, иначе
  по зелёной шкале — в мобильном клиенте шкалы для этого нет);
* знает, хватает ли энергии на призыв: виджет оранжевый, когда хватает,
  и серый, когда не хватает (цена призыва показана в самом виджете, и она
  растёт от призыва к призыву);
* проходит меню: «Забрать» на экране итогов, «Продолжить», «PvP», а при
  неудачном подборе — «Co-Op»;
* играет несколько раундов подряд (`--rounds`);
* снимает поп-апы клавишей «Назад», если экран не меняется от кликов;
* **не нажимает кнопки покупок**: золотая кнопка считается покупкой,
  если в ней есть цена (символ валюты или читаемые цифры) — кнопка
  «Играть» золотая, но цены в ней нет;
* не заходит в верхнюю полосу HUD: там валюты с кнопками «+» и значок
  меню «три полоски»;
* не кликает красные бейджи скидок «-90%»: у крестика окна белый глиф
  квадратный, у бейджа — широкая строка цифр.

## Что пересчитать под другой клиент

Мобильный клиент устроен иначе, чем веб-клиент: другое положение
поля, HUD и карточек. Поэтому под него снимаются заново:

* область числа энергии и область флакона;
* область зелёной шкалы энергии (`Layout.mana_bar`);
* область виджета призыва;
* ряд карточек юнитов;
* прямоугольник арены;
* порог правого края для крестика (`Layout.close_x_min`);
* эталоны цифр (`assets/digits_emulator`) и надписей (`assets/ui`).

Инструмент для проверки: `--probe` печатает, что бот видит в кадре,
`--frame` делает то же для сохранённого кадра.

## Известные ограничения

* распознавание типов юнитов и выбор, кого ставить, в C++ пока не
  перенесены: в живой игре виджет сам решает, кого звать, поэтому бот
  просто зовёт юнита, когда хватает энергии. Порт `rrbot/vision.py` и
  `rrbot/planner.py` (`src/vision.*`, `src/planner.*`) идёт, но в живой
  цикл (`src/main.cpp`) модули пока не включены;
* в мобильном клиенте запасного источника энергии нет: шкала тёмная, по
  цвету не читается, область `Layout.mana_bar` пустая — число читается
  только по цифрам;
* `--learn` работает только с `--frame`;
* `--learn-dir` должен существовать заранее: бот считает образцы в
  каталоге до записи, и на несуществующем каталоге падает с
  `filesystem_error` (скрипт `collect_emulator_digits.py` создаёт каталог
  сам);
* окно с отметками кликов (`cv::imshow`, ключ `--show`) под Wayland не
  открывается: кадры с отметками складываются в `--out`;
* путь к каталогу `assets` ищется рядом с бинарником, а если не найден —
  берётся жёстко прописанный `/home/lennistyle/rushroyale-lab`.
